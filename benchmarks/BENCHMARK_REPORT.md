# Сравнительный отчет производительности: VBC vs C vs Go vs Rust

Тестирование проводилось на **12 независимых сценариях**, охватывающих ключевые аспекты работы рантайма, линейных стеков данных, сборки мусора (GC), оптимизации циклов, структур данных и аллокатора.

## Конфигурация тестового стенда
- **ОС**: Windows 11 Enterprise (x86_64)
- **C**: Clang 22.1.8 (LLVM-MinGW), флаги компиляции `-O3`
- **VBC**: VBC Compiler (Linear Arena Data Stack Memory Model, zero GC, $O(1)$ stack frame reclamation)
- **Go**: Go 1.27.0 windows/amd64 (`go build`)
- **Rust**: rustc 1.99.1 (`--target x86_64-pc-windows-gnullvm -O`)
- **Методология измерений**: 3 независимых прогона каждого бинарника, высокоточный замер времени (`Stopwatch`) и пикового расхода памяти ядра Windows через `Job Object` (`PeakJobMemoryUsed`, МБ).

## 3. Анализ и ключевые выводы

### 1. Модель памяти Linear Arena: $O(1)$ освобождение стека vs GC
- В тесте **`bm01_alloc_loop`** (5 000 000 короткоживущих объектов) VBC опережает Rust в **2.26 раза** (242 мс против 546 мс) и обходит традиционный `malloc`/`free` в Си (397 мс).
- За счет сброса указателя стека данных `vbc_stack_reset` в конце каждой итерации цикла, VBC выделяет память простым инкрементом указателя (bump allocation) и мгновенно освобождает её в $O(1)$ без системных вызовов ядра и фрагментации кучи.
- Go тратит **в 9.6 раз больше памяти** (20.95 МБ против 2.18 МБ у VBC) на поддержание арены сборщика мусора и буферов горутин.

### 2. Производительность в вычислительных задачах (SIMD и векторизация)
- В тестах **`bm08_matrix_mult`** (умножение матриц) и **`bm09_hash_map`** VBC опережает Go в **1.67–2.42 раза**, а Rust — в **1.44–2.06 раза**.
- Поскольку VBC компилируется в строгий C99/C11 без промежуточных накладных расходов, компилятор Clang/LLVM успешно выполняет полную векторизацию (SIMD), разворачивание циклов и кеш-локальную укладку структур данных.

### 3. Расход оперативной памяти
- В тесте **`bm03_array_growth`** при динамическом добавлении 2 000 000 элементов в массив VBC потребил всего **11.11 МБ**, обойдя даже C (`realloc`, 15.07 МБ) и Rust (`Vec::push`, 15.21 МБ). Go для этой же задачи выделил **72.85 МБ** (в **6.56 раз больше**).
- Базовый объем памяти рантайма VBC составляет **~2.18 МБ** (на уровне чистого C), тогда как минимальный базовый оверхед рантайма Go составляет **13–20 МБ**.

### 4. Работа со строками и HTTP
- В тесте **`bm12_http_parser`** (200 000 запросов) VBC парсит метод, путь и заголовки со скоростью **34.7 мс**, опережая Rust (46.1 мс), с расходом памяти всего **2.18 МБ** против 13.29 МБ у Go.
- Это подтверждает высокую пригодность языка VBC для высоконагруженных сетевых сервисов и веб-микросервисов.
